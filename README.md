# Автоматизация тестирования личного кабинета преподавателя Skyeng

Дипломный проект по направлению «Тестирование ПО».

## О проекте

Проект содержит автоматизированные тест-сценарии для проверки личного кабинета
преподавателя Skyeng: API-тесты расписания и авторизации, а также UI-тесты
ключевых пользовательских сценариев (Selenium).

Объект тестирования:

- Личный кабинет преподавателя: <https://teachers.skyeng.ru>
- API: <https://api-teachers.skyeng.ru>
- Документация API — Cookie-based authentication, параметр `token_global` в заголовке Cookie.
  Коды ошибок: `401 Unauthorized` — невалидный или отсутствующий токен,
  `403 Forbidden` — недостаточно прав для выполнения операции.

    └── README.md

## Тестовое окружение

- Windows 10/11, Python 3.11+
- Google Chrome (WebDriver устанавливается автоматически)
- pytest, selenium, requests, allure-pytest

## Установка

    pip install -r requirements.txt

В `config.py` указывается персональное значение куки `token_global` действующей
сессии личного кабинета преподавателя — значение берётся из браузера после
авторизации и действует до выхода из аккаунта.

## Запуск тестов

    py -m pytest tests -q

Отдельные наборы:

    py -m pytest tests/test_auth.py -q         # авторизация (быстрые, ~4 сек)
    py -m pytest tests/test_events.py -q       # расписание
    py -m pytest tests/test_ui_priority.py -q  # UI-сценарии (требуется Chrome)

## Формирование Allure-отчёта

    py -m pytest tests --alluredir=allure-results -q
    allure serve allure-results

## Итоговый результат прогона

**25 passed, 1 skipped, 4 xfailed — 0 failed, 0 errors.**

Пометка xfail означает: тест фиксирует зарегистрированное расхождение, ожидаемое
поведение не реализовано, сценарий воспроизводится стабильно.

| Тест | Причина xfail |
|---|---|
| `test_auth.py::test_fake_token` | Баг BR-001: `token_global` не валидируется — при фейковом значении токена сервер отвечает 200 вместо 401 (по документации должен быть `401 Unauthorized`). Баг передан разработчикам. |
| `test_events.py::…` (2 теста) | Известные расхождения текущей реализации API с требованиями, зафиксированы при разведочном тестировании. |
| `test_ui_priority.py::test_ac2_created_later_starts_earlier` | Контрольная проверка гипотезы AC2: порядок событий в DOM определяется не временем создания, как предполагается в критерии. Расхождение документировано. |

Skip (1 тест) — отключён с указанием причины в декораторе.

## Находки, ценные для отчёта

1. **BR-001 (дефект контроля доступа).** Значение `token_global` не проверяется
   на валидность: запрос с подменённым токеном возвращает 200 и полный список
   событий. При этом невалидная сессия корректно отсекается (401). Противоречит
   документации («401 Unauthorized — невалидный или отсутствующий токен»).
2. **Расхождение с AC2.** Порядок отображения событий на странице «Расписание»
   не соответствует предположению критерия AC2 («созданное позже — выше»):
   контрольный тест показал, что порядок зависит от другой характеристики
   (время начала события).
